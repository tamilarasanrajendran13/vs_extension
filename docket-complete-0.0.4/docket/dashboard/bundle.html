Gates

What each gate caught that everything upstream let through, with every recorded state in its own column. Ran counts decisions (pass + fail) - policy skips, unknowns and never-reached rows never enter the pass-rate denominator. The roll-up scores each run's latest durable row: the ledger is append-only, so a gate that failed and then passed on repair counts once, as its latest durable row. A measured zero renders 0 in every cell; only a value nobody measured earns the dash. Each gate's full name and purpose is shown in the first column.

Findings - the investigation workspace

Docket's primary metric as evidence you can walk: every recorded finding, its resolution chain, and the repair economics behind it. Lifecycle and taxonomy are two vocabularies over the same rows and are never summed. CONFIRMED is a lifecycle fact - a claim that survived triage - not automatically a defect.

Evidence browser

Every attempt's artifact rows, searchable and filterable. The ledger records paths and hashes; content stays in the workspace. The visible sha is a ten-character display prefix - Copy carries all 64 characters, and a clipboard the host refuses produces an honest failure, never a silent no-op. Paths are never auto-linked; containment decides host-open eligibility.

The agent roster

Every actor the payload returns - what it does, what it reads and writes, and how much it has run. Actor types and capability pills come from the roster (agent_info), never inferred from whether historical model rows happen to exist. "Has recorded activity" means ledger rows exist in scope - there is no live actor state to report.

The database

The ledger is append-only: events and checkpoints by trigger; gates and findings supersede with later rows, never updates in place. It is the source of truth, and this dashboard is not the only reader - loop.py, the knowledge system and the run monitor all read the same file. Facts below are measured by the payload builder; a value nobody measured is a dash with its reason.

The rest of the ledger

Tables nobody told the dashboard about. Found by reading your schema, not by being described. Inventory counts cover the whole ledger - every project - while the other tabs are scoped to the selected project; the two denominators are never mixed.
