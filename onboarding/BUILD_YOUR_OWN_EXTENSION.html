Hands-on tutorial — start to finish

Build Your Own Docket

From an empty folder to a signed-and-sealed .vsix file you can install and hand to a colleague. You will build a minimal VS Code extension with a small UI, wire it to a Python script, and have that Python ask GitHub Copilot a real question — the same architecture the full Docket uses, in about 200 lines.

~45 minutes 8 steps 7 files no frameworks no build step

0Set up and verify

Prove your machine is ready before you write a line of code

Four things. Check each one now, because every later step assumes it, and a missing piece is much cheaper to find here than at step 6.

Verify your toolchain
terminal
node --version      # need any recent version. Used to build the .vsix.
python3 --version   # need Python 3. On Windows this is usually `python`.
code --version      # the VS Code CLI. See the note below if this fails.

Then, inside VS Code, confirm Copilot is signed in: look at the account icon in the bottom-left. You need an active GitHub Copilot subscription, and your organisation must allow extensions to use it.

If "code --version" is not found

On macOS the CLI is not installed by default. Open VS Code, press Cmd+Shift+P, and run Shell Command: Install 'code' command in PATH. On Windows and Linux it is normally added by the installer.

You only need it for step 7. Everything else works without it.

1The smallest extension that works

Two files, one command, and F5

Create the folder
terminal
mkdir -p hello-docket/.vscode hello-docket/test
cd hello-docket

File 1: package.json — the manifest

This is the first thing VS Code reads. It declares what your extension is called, what commands it offers, and which VS Code versions it supports.

package.json
create this file
{
  "name": "hello-docket",
  "displayName": "Hello Docket",
  "description": "A minimal extension that asks Copilot a question from Python.",
  "version": "0.0.1",
  "publisher": "your-name",
  "license": "MIT",
  "engines": {
    "vscode": "^1.95.0"
  },
  "categories": ["Other"],
  "main": "./extension.js",
  "contributes": {
    "commands": [
      {
        "command": "hello.sayHi",
        "title": "Hello: Say Hi"
      }
    ]
  }
}
Every field, and why it is there
FieldWhat it does
nameThe internal id. Lowercase, no spaces. Combined with publisher it becomes the unique extension identifier.
displayNameWhat humans see in the Extensions list.
versionMust be x.y.z. The packager refuses anything else, and the filename comes from it.
publisherRequired to package. Any string works for local use; you only need a registered publisher to publish to the Marketplace. Put your name.
engines.vscodeMinimum VS Code version. Also what tells VS Code this folder is an extension at all.
mainThe file to load. No build step, so it points straight at your source.
contributes.commandsWhat appears in the command palette. command is the id you register in code; title is what the user types.
There is no activationEvents field, and that is correct

Older tutorials tell you to add "activationEvents": ["onCommand:hello.sayHi"]. Since VS Code 1.74 that is generated automatically from contributes.commands. Adding it by hand is harmless but redundant.

File 2: extension.js — your code

extension.js
create this file
// VS Code injects this module at runtime. You never install it.
const vscode = require("vscode");

// Called once, the first time one of your commands is invoked.
function activate(context) {
  context.subscriptions.push(
    vscode.commands.registerCommand("hello.sayHi", function () {
      vscode.window.showInformationMessage("Hello from your first extension!");
    })
  );
}

// Called when VS Code shuts your extension down. Nothing to clean up yet.
function deactivate() {}

module.exports = { activate, deactivate };

Three things worth noticing:

  • require("vscode") is not an npm package. VS Code supplies it at runtime. This is why there is no node_modules and nothing to install.
  • The string in registerCommand must exactly match the command in package.json. A mismatch is the most common beginner bug and produces "command not found".
  • Pushing into context.subscriptions is how you get cleaned up automatically on shutdown.

Run it

  1. Open the hello-docket folder in VS Code — that folder itself, not a parent.
  2. Press F5 (or Fn+F5, or Run > Start Debugging).
  3. A second window opens with [Extension Development Host] in its title.
  4. In that window: Ctrl+Shift+P / Cmd+Shift+P, type Hello: Say Hi, press Enter.
Checkpoint 1

A notification appears in the bottom-right saying "Hello from your first extension!"

If it does not, the two most likely causes are: you opened the wrong folder (VS Code must see package.json at the root), or you ran the command in the wrong window. The commands only exist in Window 2.

The two-window model, once

You will do this dance all tutorial, so internalise it now. Window 1 is where you edit. Window 2 is where your extension runs. After editing extension.js, reload Window 2 with Ctrl+R / Cmd+R to pick up the change.

const vscode = require("vscode");

function activate(context) {
  context.subscriptions.push(
    vscode.commands.registerCommand("hello.sayHi", function () {
      vscode.window.showInformationMessage("Hello from your first extension!");
    }),
    vscode.commands.registerCommand("hello.openPanel", function () {
      openPanel(context);
    })
  );
}

function openPanel(context) {
  const panel = vscode.window.createWebviewPanel(
    "helloDocket",                // internal view type
    "Hello Docket",               // the tab title
    vscode.ViewColumn.One,        // which editor column
    { enableScripts: true }       // off by default; we need JS
  );

  panel.webview.html = pageHtml();

  // The panel can only reach us by posting a message.
  panel.webview.onDidReceiveMessage(async function (msg) {
    if (msg.type !== "ask") return;
    // Step 3 replaces this echo with a real answer.
    panel.webview.postMessage({ type: "answer", text: "you said: " + msg.text });
  });
}

  // The var(--vscode-*) values are supplied by the host, so the panel
  // follows whatever theme the user has chosen. No colours hardcoded.

         color: var(--vscode-foreground); }
  textarea { width: 100%; height: 90px; font-family: var(--vscode-editor-font-family);
             background: var(--vscode-input-background);
             color: var(--vscode-input-foreground);
             border: 1px solid var(--vscode-input-border, transparent); padding: 8px; }
  button { margin-top: 10px; padding: 6px 16px; cursor: pointer;
           background: var(--vscode-button-background);

  button:hover { background: var(--vscode-button-hoverBackground); }
  #out { margin-top: 18px; white-space: pre-wrap; line-height: 1.55;
         border-left: 3px solid var(--vscode-focusBorder); padding-left: 12px; }
  .muted { opacity: .6; }

  <h3>Ask Copilot</h3>
  <textarea id="q" placeholder="Type a question..."></textarea>
  <button id="go">Ask</button>

  const vscode = acquireVsCodeApi();      // provided by the host

Checkpoint 2

A tab titled "Hello Docket" opens with a text box and an Ask button. Type anything, click Ask, and it echoes "you said: ..." back.

You now have a UI and two-way messaging. Everything after this is replacing that echo with a real answer.

Three things people trip on

enableScripts: true is required. Webviews run with JavaScript disabled by default. Without it, your button does nothing and there is no error.

The Content-Security-Policy line is not optional in spirit. A webview can load anything unless you stop it. default-src 'none' means nothing loads unless explicitly allowed.

acquireVsCodeApi() may only be called once per page load. Calling it twice throws.

3Add the Python bridge

Move the logic out of JavaScript and into a plain script

Right now your extension does everything. That is fine for a toy and wrong for anything real: JavaScript inside an extension host is hard to test, hard to run headless, and locks you to one editor forever.

So we invert it. Python owns the logic; the extension becomes a relay. They talk over a plain pipe, one JSON object per line.

File: ask.py

ask.py
create this file
#!/usr/bin/env python3
"""
ask.py - owns the logic. Knows nothing about VS Code.

Reads a question from argv, asks the bridge for an answer, prints
progress. Run it directly and it will explain itself.
"""

import json
import sys


class Bridge:
    """Our end of the pipe.

        we write   {"id": 1, "method": "chat", "params": {...}}
        we read    {"id": 1, "result": {...}}
                or {"id": 1, "error":  {"message": "..."}}

    THE RULE: stdout IS THE WIRE. Never print() to it. Anything that is
    not protocol corrupts the stream. Human output goes to stderr, or
    travels as a "progress" notification.
    """

    def __init__(self):
        self._id = 0

    def _send(self, obj):
        sys.stdout.write(json.dumps(obj) + "\n")
        sys.stdout.flush()

    def call(self, method, params=None):
        self._id += 1
        self._send({"id": self._id, "method": method, "params": params or {}})
        line = sys.stdin.readline()
        if not line:
            raise SystemExit("bridge closed the pipe")
        msg = json.loads(line)
        if "error" in msg:
            raise RuntimeError(msg["error"].get("message", "unknown error"))
        return msg.get("result")

    def say(self, text):
        """A notification: no id, so no reply is ever sent."""
        self._send({"method": "progress", "params": {"text": text}})


SYSTEM = "You are a concise assistant. Answer in at most four sentences."


def main():
    question = sys.argv[1] if len(sys.argv) > 1 else "Say hello."
    bridge = Bridge()
    try:
        reply = bridge.call("chat", {"system": SYSTEM, "user": question})
        bridge.say(reply.get("text", ""))
        # null, never 0: a host that cannot count tokens has told us
        # nothing, and 0 would be a measurement.
        tin = reply.get("tokens_in")
        bridge.say("\n[{} | in {} | out {}]".format(
            reply.get("model"),
            "-" if tin is None else tin,
            "-" if reply.get("tokens_out") is None else reply.get("tokens_out")))
    except Exception as e:
        bridge.say("FAILED: {}".format(e))
        return 1
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

extension.js
add this function
function runPython(context, question, panel) {
  const script = path.join(context.extensionPath, "ask.py");
  // -u = unbuffered, or the pipe stalls and nothing ever arrives.
  const child = spawn(PYTHON, ["-u", script, question], {
    cwd: context.extensionPath,
  });

  let answer = "";

  child.on("error", function (e) {
    panel.webview.postMessage({
      type: "answer",
      text: "could not start " + PYTHON + ": " + e.message,
    });
  });

  // stderr is for humans, stdout is the wire. Never mix them.
  child.stderr.on("data", function (d) {
    console.error("[python] " + String(d).trimEnd());
  });

  child.on("close", function () {
    panel.webview.postMessage({
      type: "answer",
      text: answer || "(no output)",
    });
  });

  // Read the wire one COMPLETE LINE at a time. A chunk from a pipe can
  // split anywhere, so buffer until a newline arrives.
  let buf = "";
  child.stdout.setEncoding("utf8");
  child.stdout.on("data", async function (chunk) {
    buf += chunk;
    let nl;
    while ((nl = buf.indexOf("\n")) >= 0) {
      const line = buf.slice(0, nl);
      buf = buf.slice(nl + 1);
      if (!line.trim()) continue;

      const msg = JSON.parse(line);

      // No id = a notification. Display it, never reply.
      if (msg.id === undefined) {
        if (msg.method === "progress") answer += msg.params.text + "\n";
        continue;
      }

      // A request. Step 4 makes this call a real model.
      const result = { text: "(not wired to Copilot yet)", model: "none",
                       tokens_in: null, tokens_out: null };
      child.stdin.write(JSON.stringify({ id: msg.id, result: result }) + "\n");
    }
  });
}

Test the Python on its own

Because ask.py has no VS Code dependency, you can run it in a terminal right now: python3 ask.py "hello". It will print its JSON request and then exit when stdin closes. That is the whole point of this arrangement — the logic is testable without an editor.

4Connect to real Copilot

One API call, and the reason this architecture exists

Why the Python cannot do this itself

vscode.lm is only reachable from inside a running VS Code extension host. Not from a terminal, not from a cron job, not from a server. No flag or token changes that.

So the model call has to happen in extension.js, and the Python has to ask for it. Everything you just built exists to bridge exactly that gap.

Replace the placeholder reply from step 3 with a real call. Swap the two lines that build result for this:

extension.js
replace the placeholder result

      try {
        const result = await chat(msg.params);
        child.stdin.write(JSON.stringify({ id: msg.id, result: result }) + "\n");
      } catch (e) {
        child.stdin.write(JSON.stringify({
          id: msg.id,
          error: { message: String((e && e.message) || e) },
        }) + "\n");
      }

Then add the function that does the work:

extension.js
add this function
async function chat(params) {
  const models = await vscode.lm.selectChatModels({ vendor: "copilot" });
  if (!models.length) {
    // selectChatModels returns an EMPTY ARRAY for an unknown family -
    // it does not throw. So check, or you fail silently at 2am.
    throw new Error(
      "No language models are visible to extensions. Sign in to Copilot, " +
      "or ask your admin to enable Editor Preview Features."
    );
  }
  const model = models[0];

  // A FRESH message list every call. There is no session on the provider;
  // context is only ever the bytes you resend. If this function ever
  // accumulates history, that guarantee is gone.
  const messages = [
    vscode.LanguageModelChatMessage.User(params.system),
    vscode.LanguageModelChatMessage.User(params.user),
  ];

  const cts = new vscode.CancellationTokenSource();
  const resp = await model.sendRequest(messages, {}, cts.token);

  // The answer STREAMS. Collect the fragments.
  let text = "";
  for await (const frag of resp.text) text += frag;

  // An empty stream is a FAILURE, not a successful empty answer.
  // Returning "" here would make the caller fail later, far from the cause.
  if (!text.trim()) throw new Error("the model returned an empty result");

  // null, never 0. A model that cannot count tokens has told us nothing
  // about the size of this prompt; 0 would be a measurement.
  let tokensIn = null, tokensOut = null;
  try { tokensIn = await model.countTokens(params.system + params.user); }
  catch (_) { /* not all models implement it */ }
  try { tokensOut = await model.countTokens(text); } catch (_) {}

  return { text: text, model: model.family,
           tokens_in: tokensIn, tokens_out: tokensOut };
}
Checkpoint 4 — the big one

Reload Window 2, open the panel, ask a real question. You should get a real Copilot answer, followed by a line like:

[claude-sonnet-4 | in 24 | out 61]

You have just built the entire Docket architecture in miniature.

What you would add next, in a real product

The full gateway.js is about 1,585 lines because it also handles: resolving a model by role rather than taking the first one; routing concurrent requests by id; a typed error taxonomy so a refusal, an exhausted quota and a timeout are different facts; retries with backoff; per-request timeouts and cancellation; and scrubbing secrets out of every line before it reaches a permanent log.

None of that changes the shape you just built. It is all detail hung off these same four message types.

5Test it without VS Code

A headless check you can run in CI

Pressing F5 and clicking is a manual test. It does not scale, and it cannot run in CI. So we fake the vscode module and drive the real activate().

The trick: Node lets you intercept require. We install a fake vscode before loading extension.js, so the extension loads normally and never knows.

test/check.js
create this file
// check.js - drive the real extension against a fake VS Code.
// No editor, no Copilot, no network.  Run:  node test/check.js

"use strict";

const path = require("path");
const Module = require("module");

let passed = 0, failed = 0;
function ok(name, cond) {
  if (cond) { passed++; console.log("  [ok  ] " + name); }
  else      { failed++; console.log("  [FAIL] " + name); }
}

// ---- the fake host -------------------------------------------------
const commands = {};
const posted = [];
let messageHandler = null;

const fakeVscode = {
  ViewColumn: { One: 1 },
  commands: {
    registerCommand(id, fn) { commands[id] = fn; return { dispose() {} }; },
  },
  window: {
    showInformationMessage(text) { posted.push({ info: text }); },
    createWebviewPanel() {
      return {
        webview: {
          html: "",
          postMessage(m) { posted.push(m); },
          onDidReceiveMessage(fn) { messageHandler = fn; },
        },
      };
    },
  },
  // The model API. Returns a fixed answer - zero real calls.
  lm: {
    async selectChatModels() {
      return [{
        family: "fake-model",
        async countTokens(s) { return s.length; },
        async sendRequest() {
          return { text: (async function* () { yield "a fake answer"; })() };
        },
      }];
    },
  },
  LanguageModelChatMessage: { User: (t) => ({ role: "user", content: t }) },
  CancellationTokenSource: function () { this.token = {}; },
};

// Intercept require("vscode") BEFORE the extension is loaded.
const realLoad = Module._load;
Module._load = function (request, parent, isMain) {
  if (request === "vscode") return fakeVscode;
  return realLoad.apply(this, arguments);
};

const ext = require(path.join(__dirname, "..", "extension.js"));

// ---- the checks ----------------------------------------------------
console.log("\nhello-docket checks\n");

const context = { subscriptions: [], extensionPath: path.join(__dirname, "..") };
ext.activate(context);

ok("activate registers hello.sayHi", typeof commands["hello.sayHi"] === "function");
ok("activate registers hello.openPanel", typeof commands["hello.openPanel"] === "function");
ok("subscriptions were registered for cleanup", context.subscriptions.length >= 2);

commands["hello.sayHi"]();
ok("sayHi shows a message", posted.some((p) => p.info && /Hello/.test(p.info)));

commands["hello.openPanel"]();
ok("openPanel wires a message handler", typeof messageHandler === "function");

// The manifest and the code must agree, or the command is unreachable.
const manifest = require(path.join(__dirname, "..", "package.json"));
const declared = manifest.contributes.commands.map((c) => c.command).sort();
const registered = Object.keys(commands).sort();
ok("every declared command is registered",
   JSON.stringify(declared) === JSON.stringify(registered));

ok("manifest version is x.y.z", /^\d+\.\d+\.\d+$/.test(manifest.version));
ok("manifest has a publisher (required to package)", !!manifest.publisher);
ok("main points at a real file",
   require("fs").existsSync(path.join(__dirname, "..", manifest.main)));

console.log("\n" + passed + " passed, " + failed + " failed\n");
process.exit(failed ? 1 : 0);
Run the checks
terminal

Checkpoint 5

You should see nine [ok ] lines and 9 passed, 0 failed. The process exits non-zero on failure, so this drops straight into CI.

The check that earns its keep

"every declared command is registered" compares package.json against what the code actually registered. That mismatch is the single most common extension bug — you rename a command in one place and not the other, and the palette entry silently does nothing. A human would not catch it; this does, instantly.

Control what goes in the package

By default everything in the folder is included — your tests, your .vscode folder, any stray notes. Use an allowlist instead: ignore everything, then re-include exactly what the installed extension needs at runtime.

.vscodeignore
create this file
# Allowlist form: ignore everything, then re-include what is needed
# at RUNTIME. Safer than a denylist - a new file is excluded by
# default rather than accidentally shipped.
**
!package.json
!extension.js
!ask.py
!README.md
!LICENSE.txt
Why allowlist, not denylist

With a denylist, every new file you add ships unless you remember to exclude it. That is how credentials, scratch notes and internal test fixtures end up inside published packages. With an allowlist, a new file is excluded by default and shipping it is a deliberate act.

If you see test/, .vscode/ or node_modules/ in there, your .vscodeignore is not being picked up — check it is at the folder root and named exactly that, with the leading dot.

Do not be alarmed by "readme.md"

You will notice README.md came out as readme.md. Some versions of vsce normalise the readme and license entry names to lowercase. It is the same file, and it is expected.

Errors you may hit here

"Missing publisher name" — add "publisher" to package.json. Any string works locally.

"Invalid version" — it must be exactly x.y.z. No v prefix, no suffix.

"A LICENSE file is missing" — add LICENSE.txt, or pass --skip-license if you truly do not want one.

7Install it and test for real

Run it as a proper installed extension, not a dev host

Until now you have only run in the Extension Development Host, which is temporary and forgiving. Installing the .vsix is the real test.

Install from the terminal
terminal
code --install-extension hello-docket-0.0.1.vsix

# confirm it is there (identifier is publisher.name)
code --list-extensions | grep hello-docket

Or through the UI: open the Extensions view, click the ... menu at the top of the panel, and choose Install from VSIX....

Now test it properly

  1. Fully quit and reopen VS Code. Not just reload — quit.
  2. Open any folder. Your extension should work regardless of what is open.
  3. Run Hello: Open Panel from the palette.
  4. Ask a question. You should get a real answer.
Checkpoint 7 — you are done

It works in a normal VS Code window, from a file you could email to someone. That file is a complete, self-contained extension: no build, no dependencies, no install steps for the recipient beyond Copilot and Python.

The failure this step exists to catch

An extension that works under F5 and breaks once installed almost always means a file it needs was excluded from the package. The dev host reads your whole folder; the installed extension only has what the .vsix contains.

Classic symptom: "could not start python: ENOENT ... ask.py". You forgot !ask.py in .vscodeignore. This is exactly why checkpoint 6 has you list the archive contents.

Uninstall when you are finished
terminal
code --uninstall-extension your-name.hello-docket

Shipping a new version

  1. Bump version in package.json. VS Code will not reinstall over the same version.
  2. Run node test/check.js and confirm it is green.
  3. Re-run the vsce package command with the new filename.
  4. unzip -l the result and check the inventory.
  5. Install and smoke-test in a clean window.
